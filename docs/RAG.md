# RAG 设计与资料更新

[返回项目首页](../README.md)

实现入口为 [`kb_service.py`](../backend/app/services/kb_service.py)，由 Agent 的 `search_lab_docs` 工具调用。

## 当前处理流程

```text
用户问题
  → retrieve_context 自动调用 search_lab_docs
  → get_collection() 切片并同步本地文档
  → 将问题转换为向量并检索 Chroma
  → 距离换算、阈值过滤、保留最多三个片段
  → 将带文件名及片段编号的正文返回模型
  → 模型结合工具结果生成回答
```

每轮先由图的 `retrieve_context` 节点用最新用户消息调用已有检索工具，再执行模型节点。需要补充检索时，模型仍可调用 `search_lab_docs`；真实库存及预约状态继续使用数据库工具。检索返回后会在本次模型输入中补充“按资料直接回答、不主动扩展方案”的约束。

自动检索包含寒暄和业务查询，会增加一次本地检索及上下文长度，没有额外增加生成模型调用。失败或空结果也作为明确工具结果交给模型。程序保证先执行检索，但当前没有对最终答案自动做引用或语义支持校验，不能据此保证零幻觉。

## 数据与索引

| 项目 | 当前设置 |
| --- | --- |
| 文档目录 | `backend/data/kb/` |
| 支持范围 | 目录第一层的 `*.md`，不递归扫描子目录 |
| 文本读取 | `utf-8-sig`，去除首尾空白 |
| 片段 ID | `{path.stem}::chunk::{chunk_index}`，编号从 0 开始 |
| 元数据 | `source` 保存原文件名，`chunk_index` 保存片段编号 |
| 向量模型 | `BAAI/bge-small-zh-v1.5`，本地 Sentence Transformers |
| Chroma 路径 | `backend/data/chroma/` |
| Collection | `lab_kb` |
| 分块策略 | 每片最多 500 字符，相邻窗口重叠 80 字符；片段首尾去空白、跳过空片段 |

目前资料包括预约规则、安全规范、开放时间、通用设备使用，以及电子显微镜、示波器、离心机三份设备说明。除开放时间外，其余资料扩展为可产生多个片段的长文档，由 `text_splitter.py` 拆分后逐片入库。当前没有 PDF 解析、按标题或段落切分、重排序或混合检索。

设备说明是通用教学资料，不构成真实库存、型号能力或已实施培训流程的证明。实际资源和维修状态由数据库工具查询；具体实验参数遵循设备型号说明和现场规程，不在示例资料中编造。

设备基础说明参考厂商公开资料，并按项目场景编写：

- [JEOL：扫描电子显微镜及样品准备](https://www.jeol.com/products/science/sem.php)
- [JEOL：非导电样品与导电镀膜的选择](https://www.jeolusa.com/RESOURCES/Sample-Preparation/Documents-Downloads/sample-coating-for-sem)
- [Tektronix：示波器与探头使用基础](https://www.tek.com/en/documents/primer/setting-and-using-oscilloscope)
- [Eppendorf：离心机安全与装载](https://www.eppendorf.com/ae-en/lab-academy/life-science/cell-biology/centrifuge-safety/)

字符数不等于 token 数；当前使用字符窗口，未实现严格的 token 预算。切片可能截断句子，重叠窗口用于保留部分相邻上下文。

业务资料随仓库提交；向量索引作为可重建的运行产物由 `.gitignore` 排除。每次同步按当前切片规则比较正文并清理旧 ID，首次使用新代码会替换旧整篇记录。更换向量模型时仍需重建索引；同步逻辑不能自动识别模型配置变化。

## 文档同步

`get_collection()` 复用缓存的 Collection，但每次调用都会先同步文档。同步步骤为：

1. 确认知识库目录存在，避免把目录配置错误误认为所有文档都已删除。
2. 读取库内的 ID 和原文，建立 `ID → 原文` 的字典。
3. 读取本地非空 Markdown，切片并记录当前所有有效片段 ID。
4. 新增或原文发生变化的记录调用 `upsert()`，更新文档、元数据和向量。
5. 库中存在、但本地已不再有效的 ID 调用 `delete()`。

| 文件操作 | 下次同步的行为 |
| --- | --- |
| 新增文件 | 为所有片段新增记录并生成向量 |
| 修改正文 | 更新有变化的片段；文档缩短时删除多余旧片段 |
| 内容不变 | 跳过，不重复生成向量 |
| 删除或清空文件 | 删除该文件的全部旧片段 |
| 重命名文件 | 按新文件名生成片段 ID，并删除旧 ID |

同步完成后才继续检索。因此资料保存后，下次知识库工具调用可使用新内容；已经生成的回答不回写，已开始的查询也不承诺实时切换资料版本。同步异常会向调用方传播，工具返回错误信息。

`_kb_lock` 保护同一进程中的初始化和同步过程。它不构成跨进程锁，也不提供多文件更新与查询之间的事务快照。当前 `lab_kb` 整体由该本地目录维护，不应混入其他来源的独立记录，否则这些记录可能在同步时被移除。

## 检索与筛选

1. 空库返回空字符串，工具将其转换为“没有检索到相关的资料”。
2. 召回条数为 `min(5, col.count())`。
3. 对返回的距离使用 `score = 1 / (1 + distance)` 进行换算。
4. 丢弃 `score < 0.5` 的结果，再按分数降序排列。
5. 最多返回三个片段，格式为 `[原文件名 · 片段 N]\n片段正文`，展示编号从 1 开始。同一文件可返回多个片段。

该分数是项目使用的启发式换算，不是经过校准的置信概率。最终返回条数已做开发集对照实验，阈值未作独立校准或独立测试集验证。工具预览会截断较长输出，但完整工具结果仍传给模型。

## 回归测试

在 `backend` 目录执行 `.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_kb_service.py -v`。
测试使用临时 Markdown 和模拟 Collection，覆盖切片边界、片段同步、旧整篇记录清理、修改及删除、写入失败，以及检索输出的编号、排序和过滤；不调用真实向量模型。

`test_agent_retrieval.py` 另用真实图、实际工具包装及模拟模型检查自动检索先于回答、每轮使用最新问题、调用 ID 唯一、失败及空结果、后续数据库工具与 SSE 保存链路。这些测试不衡量真实模型的回答质量。

## 如何更新资料并验证

1. 修改 `backend/data/kb/` 下的 Markdown，保存为 UTF-8。
2. 在聊天中重新询问需要该资料的问题，确认有知识库工具调用。
3. 查看工具输出预览或后端检索日志，核对新增的句子或修改内容。
4. 如果旧对话已包含相反回答，刷新聊天页面开启新对话，区分旧聊天上下文与旧索引的影响。

本地开发时只改资料通常无需重启。Docker 模式下，Markdown 文件在构建时复制进镜像，保存后需要在仓库根目录执行 `docker compose up -d --build backend`。预热后再用实际问题检查召回内容。

## 规则与后端的一致性

知识库用于向用户解释业务规则，后端业务服务决定操作是否允许。例如“只有学生可预约”已经在 `create_reservation()` 中校验，模型即使回答错误，也不应绕过此校验。

预约资料已与当前取消接口统一：本人只能自行取消待审核的正式预约，已通过的预约需联系管理员处理。设备预约需要绑定所属实验室，但不应描述为自动独占整间实验室或获得全部设备使用权。

## 评测开发集

已整理 25 条人工标注开发题，包含 20 条资料内问题、3 条资料外问题、2 条需要真实业务数据的问题，覆盖直接提问、同义改写、长文档中后段以及多来源问题。题库、判分方式和进度见 [RAG 评测](RAG_EVAL.md)。

资料内开发题的严格标注依据覆盖率，在最终返回片段数从 2 改为 3 后，由 18/20（90%）变为 20/20（100%），详细记录及判分限制见 [RAG 评测](RAG_EVAL.md)。3 条资料外问题和 2 个业务工具场景已完成手工检查并记录范围及措辞限制。覆盖率不是回答准确率；20 条资料内问题的最终生成答案尚未逐题核对。
