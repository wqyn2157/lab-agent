# RAG 设计与资料更新

[返回项目首页](../README.md)

实现入口为 [`kb_service.py`](../backend/app/services/kb_service.py)，由 Agent 的 `search_lab_docs` 工具调用。

## 当前处理流程

```text
用户问题
  → Agent 选择 search_lab_docs
  → get_collection() 同步本地文档
  → 将问题转换为向量并检索 Chroma
  → 距离换算、阈值过滤、保留最多两篇
  → 将带文件名的原文返回模型
  → 模型结合工具结果生成回答
```

是否调用检索由模型依据工具说明和系统提示词决定；当前没有对每次问题强制执行检索，也没有对最终答案自动做引用校验。

## 数据与索引

| 项目 | 当前设置 |
| --- | --- |
| 文档目录 | `backend/data/kb/` |
| 支持范围 | 目录第一层的 `*.md`，不递归扫描子目录 |
| 文本读取 | `utf-8-sig`，去除首尾空白 |
| 文档 ID | 文件名去掉扩展名，即 `path.stem` |
| 元数据 | `source` 保存原文件名 |
| 向量模型 | `BAAI/bge-small-zh-v1.5`，本地 Sentence Transformers |
| Chroma 路径 | `backend/data/chroma/` |
| Collection | `lab_kb` |
| 分块策略 | 一篇 Markdown 对应一条向量记录 |

目前资料为预约规则、安全规范、开放时间和设备使用四份短文档，采用整篇入库。当前没有 PDF 解析、长文档分块、重排序或混合检索。

业务资料随仓库提交；向量索引作为可重建的运行产物由 `.gitignore` 排除。更换模型或分块策略时，需要重新构建对应索引，当前同步逻辑只比较文档内容，不能自动识别模型配置变化。

## 文档同步

`get_collection()` 复用缓存的 Collection，但每次调用都会先同步文档。同步步骤为：

1. 确认知识库目录存在，避免把目录配置错误误认为所有文档都已删除。
2. 读取库内的 ID 和原文，建立 `ID → 原文` 的字典。
3. 读取本地非空 Markdown，记录当前有效 ID。
4. 新增或原文发生变化的记录调用 `upsert()`，更新文档、元数据和向量。
5. 库中存在、但本地已不再有效的 ID 调用 `delete()`。

| 文件操作 | 下次同步的行为 |
| --- | --- |
| 新增文件 | 新增记录并生成向量 |
| 修改正文 | 复用相同 ID 更新正文并重新生成向量 |
| 内容不变 | 跳过，不重复生成向量 |
| 删除或清空文件 | 删除对应旧记录 |
| 重命名文件 | 按新 ID 入库，并删除旧 ID |

同步完成后才继续检索。因此资料保存后，下次知识库工具调用可使用新内容；已经生成的回答不回写，已开始的查询也不承诺实时切换资料版本。同步异常会向调用方传播，工具返回错误信息。

`_kb_lock` 保护同一进程中的初始化和同步过程。它不构成跨进程锁，也不提供多文件更新与查询之间的事务快照。当前 `lab_kb` 整体由该本地目录维护，不应混入其他来源的独立记录，否则这些记录可能在同步时被移除。

## 检索与筛选

1. 空库返回空字符串，工具将其转换为“没有检索到相关的资料”。
2. 召回条数为 `min(5, col.count())`。
3. 对返回的距离使用 `score = 1 / (1 + distance)` 进行换算。
4. 丢弃 `score < 0.5` 的结果，再按分数降序排列。
5. 最多返回两篇，格式为 `[原文件名]\n文档正文`。

该分数是项目使用的启发式换算，不是经过校准的置信概率。阈值和召回条数尚未经过固定评测集验证。工具预览会截断较长输出，但完整工具结果仍传给模型。

## 如何更新资料并验证

1. 修改 `backend/data/kb/` 下的 Markdown，保存为 UTF-8。
2. 在聊天中重新询问需要该资料的问题，确认有知识库工具调用。
3. 查看工具输出预览或后端检索日志，核对新增的句子或修改内容。
4. 如果旧对话已包含相反回答，刷新聊天页面开启新对话，区分旧聊天上下文与旧索引的影响。

只改资料通常不需要重启；修改 Python 代码或运行配置后，需要使后端重新加载。预热成功不等于答案质量已验证，仍应检查实际问题的召回内容。

## 规则与后端的一致性

知识库用于向用户解释业务规则，后端业务服务决定操作是否允许。例如“只有学生可预约”已经在 `create_reservation()` 中校验，模型即使回答错误，也不应绕过此校验。

目前资料中写有“已通过的预约也可取消”，而取消接口只接受待审核状态。该处属于待统一的规则差异，文档同步只能更新索引，不能自动修正业务含义。

## 后续评测建议

尚未建立正式评测集。可先准备约30条问题，每条记录问题、预期来源文件、答案要点和是否应该无答案，覆盖直接提问、同义改写、多文档问题、资料外问题及规则更新后的问题。

分别检查检索是否命中正确资料，以及最终回答是否忠于资料；保存版本、耗时和失败样例后再调整召回条数、阈值或分块策略。当前没有可报告的检索准确率或优化提升比例。
